ゲーム仕様は `SPEC.md`、開発計画は `PLAN.md` を参照。

このドキュメントは **「どの数値をどこで変えられるか」と「変更したとき何が壊れるか」** をまとめたもの。

## 0. 原則

- 数値の変更は **`src/engine/constants.ts` と `src/data/units.ts` の2ファイル**に集約されている(PLAN §3.3 / §309)
- **仕様が正、コードが従。** 挙動を変えるときは先に `SPEC.md` を直す
- **変更するとテストが落ちる。これは設計どおり。** 意図しない値の変化を検出するための仕掛けなので、変更が意図的なら期待値も一緒に直す(→ §3)
- **調整の良し悪しは `npm run sim` のレポートで判断する。** 感覚で動かさない(→ §3.1)

## 2. `src/data/units.ts` — ユニット別の値

各エントリを直接書き換える。

| 項目 | 例 | 備考 |
|---|---|---|
| `maxHp` | 堅牢 140 | `HP_MIN`〜`HP_MAX` の範囲内に収めること |
| `speed` | `'fast'` / `'mid'` / `'slow'` | |
| `attribute` | `'gu'` / `'choki'` / `'pa'` | 変えると属性ごと5体の均等が崩れ、テストが落ちる |
| `damage.power` | 粉砕 60 | 通常ダメージ。相性補正と修正値が乗る |
| `damage.amount` | 手のひら 20 | 固定ダメージ。全修正を無視する |
| `recoil` | 粉砕30 / 石15 / ゴースト5 | 自分が受ける固定の反動 |
| `priority` | `'first'` / `'normal'` | 先制の付け外し |
| `maxUses` | 手のひら技2 = 3 | 1試合の使用回数上限。使い切ると選べなくなる。**全技に付けると行動不能になる** |
| `name` / `text` | 技名・効果テキスト | **表示のみ。挙動に影響しない**ので自由に変えてよい |

### 新ユニットの追加

`UNITS` にエントリを1つ足すだけでよい。`UnitId` 型はデータから自動導出されるので `types.ts` を触る必要はない(PLAN §84)。

特性や特殊挙動を持たせる場合は `src/engine/effects/` に1ファイル追加し、`units.ts` の
エントリに `hooks:` として結びつける。**エンジン本体 (`battle.ts`) は触らなくてよい** (PLAN §84)。

## 3. 変更手順

```bash
# 0. 変更前のレポートを取っておく(比較の基準になる)
npm run sim -- --full
git add reports/ && git commit -m "調整前のレポート"

# 1. docs/SPEC.md を先に更新する(仕様が正、コードが従)
# 2. constants.ts / units.ts を変更する
# 3. テストを実行 — ここで意図的に落ちる
npm run test
# 4. 落ちたテストの期待値を SPEC に合わせて更新する(下表を参照)
# 5. 最終確認
npm run lint && npm run build

# 6. レポートを取り直し、git diff で変化を読む
npm run sim -- --full
git diff reports/
```

### 変更に連動して直すテスト

| 変えたもの | 直す場所 |
|---|---|
| HP / 速度 / 属性 / 名前 | `src/data/units.test.ts` の `SPEC_TABLE`(冒頭) |
| 先制・反動・選択・特性の構成 | `src/data/units.test.ts` の「個別仕様の反映」 |
| `TYPE_ADVANTAGE` / `TYPE_DISADVANTAGE` | `src/engine/damage.test.ts` の「想定撃破速度」 |
| 一閃の威力 / 積み幅 | `src/engine/damage.test.ts` の「一閃の積みテーブル」 |
| 粉砕の威力 / 反動 / HP | `src/engine/damage.test.ts` の「実データとの突き合わせ」 |
| ユニット固有の効果量 | `src/engine/effects/<ユニット>.test.ts` |

`SPEC_TABLE` は SPEC §9 の表を**独立に転記したもの**で、`units.ts` と突き合わせて転記ミスを検出する。
そのため HP を変えると必ず2箇所を直すことになる。これは冗長ではなく、
「片方だけ書き換えてしまった」を捕まえるための二重化。

> **補足:** PLAN §309 は「数値変更が `constants.ts` と `data/units.ts` のみで完結すること」としているが、
> 実際にはテストの期待値も直す必要がある。転記ミス検出とのトレードオフ。
> Phase 7 の調整段階で煩わしければ、SPEC 由来の固定値テストを絞る方向に変えられる。

## 3.1 シミュレータ (`npm run sim`)

バランス判断の一次資料。**`reports/` は生成物なので手で編集しない。**

```bash
npm run sim                      # 3v3 を 20,000 試合抽出 (約37秒)。日常の確認用
npm run sim -- --full            # 455選出の全 103,740 試合 (約3分)。調整の記録用
npm run sim -- --mode 1v1        # 15×15 の素の対面表 (一瞬)。相性の確認用
npm run sim -- --ai1 3 --ai2 2   # AI の強さ比較
```

| オプション | 既定 | 内容 |
|---|---|---|
| `--mode 1v1\|3v3` | `3v3` | `1v1` は交代・選出を排した素の対面表 |
| `--sample N` | 20000 | 3v3 の抽出試合数 |
| `--full` | — | 総当たり全件。`--sample` を無視する |
| `--seed N` | 0 | **同じシードなら結果は完全に再現される** |
| `--ai1` / `--ai2` | 2 | 1=ランダム / 2=貪欲 / 3=先読み |
| `--max-turns N` | 300 | 超過は「未決着」として記録される |
| `--out DIR` | `reports` | 出力先 |

### 出力

| ファイル | 内容 |
|---|---|
| `summary.md` | 全指標 + 監視項目。**まずこれを読む** |
| `units.csv` | ユニット別の勝率・平均決着ターン |
| `attributes.csv` | 属性別勝率(三竦みの偏り) |
| `selections.csv` | 選出3体 455通りの勝率(3v3) |
| `matchups.csv` | 15×15 の対面表(1v1) |

### 数字の読み方

- **引き分けは 0.5勝**として数える(SPEC §8 が認めた結果であり、無効試合ではない)
- **未決着は勝率の分母から外す。** 件数だけが別に出る
- 3v3 の勝率は「そのユニットを**選出に含む陣営**が勝ったか」。個体の撃破数ではないので、
  強いユニットでも組み合わせが悪ければ下がる

### AI の重み (`src/ai/constants.ts`)

**ここはゲームバランスではない。** 変えても対戦の仕様は変わらず、AI の打ち筋だけが変わる。
ただし打ち筋が変わればレポートの数字も動くので、**調整の途中で触らないこと**(比較の基準がずれる)。

**Lv2 の資産(`evaluate.ts` / `greedy.ts` / `replacement.ts` と、このファイルの
`WEIGHT_HP` 〜 `SWITCH_MIN_HP_RATIO`)は動かさないこと。** Lv2 はシミュレータの土台で、
committed な `reports/` はその出力。1ビット変えるとレポートが現物と食い違う。
Lv3 用の値はファイル下部に分けてある。

### Lv3 の強さ — 深さがすべてだった

Lv3 に対 Lv2 の勝率を測りながら作った(両方向で確認。p1 には +1.5pt の位置的有利がある)。

| 案 | 対 Lv2 勝率 |
|---|---|
| 旧 Lv3 (深さ1・相手の手を読むだけ) | 52.9% |
| 深さ2 | 68.1% |
| 深さ3 | 74.2% |
| **深さ4** ← 現在 | **79.2%** (逆向きでも 77.1%) |
| 深さ5 | 82.6% |

**強さのつまみは `lookahead.ts` の `SEARCH_DEPTH` ただ1つ。**
1つ深くするたび約 +5pt、代わりに約4倍遅くなる。4 で止めたのは速度の余裕のため ─
深さ4 は1手あたり最悪 20ms(開発機)で、5倍遅い端末でも 100ms に収まる。

#### 効かなかった案 — 評価関数に項目を足す

「`evaluate` が対面の相性を見ていないのが最大の欠陥」と考えて、相性・控えの手当て・
技の残り回数を足した専用の評価関数を書いた。**深さ2で 64.3% と、足さない 68.1% より弱かった。**

深く読む探索は相性の損得を**実際に解決してみて**確かめている。そこに
「有利対面は +0.12」という手書きの見積もりを重ねると、読んだ結果と食い違ってノイズになる。
さらに相性項は交代を過大評価し(有利対面 0.35 > 攻撃1発 0.25)、
**両者が交代し続けて試合が終わらなくなった**(未決着 54件 → 1,723件)。

→ 浅い評価の穴を定数で埋めるより、深く読ませる。位置取りに点を付けるなら、
必ず攻撃の価値と突き合わせること。

## 5. UI 側の値

Phase 6 完了時点で全フェーズの実装が揃った。UI にも変えられる値がある。

| 対象 | 変更先 |
|---|---|
| AI の打ち筋(評価関数の重み) | `src/ai/constants.ts`。**ゲームバランスではない**(→ §3.1) |
| Lv3 の強さ | `src/ai/lookahead.ts` の `SEARCH_DEPTH`。1つ深く = 約 +5pt / 約4倍遅い |
| AI の編成 | `src/ai/draft.ts`。三属性を1体ずつ確保してから残りを一様に引く |
| 技名・効果テキスト | `src/data/units.ts` の `name` / `text`。挙動には影響しない |
| ログの言い回し | `src/ui/log.ts` |
| 画面の配色・レイアウト | `src/ui/index.css` |
| 効果音の音色 | `src/ui/audio/voices.ts` の `CUES` |
| 効果音の音量 | 同 `MASTER_GAIN` |
| どの出来事にどの音か | `src/ui/audio/cues.ts` |

### 効果音

音源ファイルは持たず、WebAudio でその場で合成する(→ `src/ui/audio/`)。
アセットもライセンス確認も追加依存も要らない代わりに、出せるのはピコピコ寄りの音に限られる。

音1つは「周波数を `from` → `to` にスイープさせるオシレータ + 短いノイズ」で、
`CUES` はその重ね方の表。数値を書き換えるだけで音が変わる。

**音の長さは再生1コマの表示時間 (`PLAYBACK_MS`) を超えてはいけない。**
超えると次のコマの音と混ざる。`src/ui/audio/cues.test.ts` が突き合わせて落とすので、
`PLAYBACK_SCALE` を下げた(速くした)ときはここが警報になる。

**乱数は使わない** (PLAN §3.4)。音程の揺らぎはダメージ量から決定的に決めており、
大きい一撃ほど低く鳴る。ノイズの波形もシード付き乱数で埋めている。

**ユニットの数値を変えたら効果テキスト (`text`) も直すこと。** 画面に常時表示され、
プレイヤーが読む唯一の説明になる(PLAN §296)。テキストは挙動に影響しないので、
テストでは検出できない。

## 6. 既知の膠着

**ゲーム側の膠着は現時点で確認されていない。** `TURN_LIMIT`(SPEC §12-3)は不要。

### 未決着として記録されるもの — AI側の都合

`npm run sim -- --full` の未決着はすべて**貪欲AIが同じ手順を繰り返す循環**で、
ゲームのルール上の膠着ではない。典型例:

```
p1: 交代→粉砕 / 交代→器 / 器の技2(控えの粉砕を10回復)
p2: 山嵐の技1(粉砕に10) / 交代→器 / 交代→山嵐
```

山嵐の10ダメージを器の技2 がちょうど10回復して打ち消し、3ターン周期で
盤面が元に戻る。AIは決定論的なので同じ選択を繰り返す。

**直すならAI側**(`src/ai/`)であって、ゲームに `TURN_LIMIT` を入れて塞ぐのは筋が違う。

### 解消済みの膠着

| 対面 | 対処 |
|---|---|
| 粉砕 vs 粉砕 | 威力50 が互角対面のHP50 に届くので、双方が同時に倒れて引き分けになる。あわせて「相手が自分の反動で自滅した場合は撃破に含めない」ことを明確化(SPEC §10.1) |
| 手のひら vs 手のひら | 技2の回復に**1試合3回**の使用回数上限を設けた。使い切ると合法手から外れ、削り合いに移る |
| 魔球 vs 魔球 | 「常に技1を使う」方針でのみ起きていた(威力が0まで減衰する)。盤面を見るAIは技2(威力15)を選ぶので発生しない |
